# Problem 1: Two Sum

## Problem Statement
Given an array of integers `nums` and an integer `target`, return indices of the two numbers such that they add up to `target`.

You may assume that each input would have **exactly one solution**, and you may not use the same element twice.

**Example 1:**
```
Input: nums = [2,7,11,15], target = 9
Output: [0,1]
Explanation: Because nums[0] + nums[1] == 9, we return [0, 1].
```

**Example 2:**
```
Input: nums = [3,2,4], target = 6
Output: [1,2]
```

**Example 3:**
```
Input: nums = [3,3], target = 6
Output: [0,1]
```

**Constraints:**
- 2 <= nums.length <= 10^4
- -10^9 <= nums[i] <= 10^9
- -10^9 <= target <= 10^9
- Only one valid answer exists.

---

## Pattern Recognition
**Pattern:** Hash Map / Complement Finding
**Difficulty:** Easy

This is a classic "find pair with sum" problem. The key insight is that for each number, we need to find its complement (target - number).

---

## Step-by-Step Explanation

### Approach 1: Brute Force (O(n²))
1. Use nested loops
2. For each element at index i, check all elements after it (index j)
3. If nums[i] + nums[j] == target, return [i, j]

**Why it's slow:** We check every pair, leading to O(n²) time complexity.

### Approach 2: Hash Map (O(n)) - OPTIMAL
1. Create a hash map to store {number: index}
2. For each number in the array:
   - Calculate complement = target - current_number
   - Check if complement exists in hash map
   - If yes, return [map[complement], current_index]
   - If no, store current_number and its index in map
3. This way, we only traverse the array once!

**Key Insight:** Instead of looking forward, we look backward using the hash map.

---

## Visual Walkthrough

Example: nums = [2,7,11,15], target = 9

```
Step 1: i=0, num=2
  complement = 9 - 2 = 7
  Is 7 in map? No
  Add {2: 0} to map
  map = {2: 0}

Step 2: i=1, num=7
  complement = 9 - 7 = 2
  Is 2 in map? YES! at index 0
  Return [0, 1] ✓
```

## Code Solutions

### Python Solution
```python
def twoSum(nums, target):
    """
    Time Complexity: O(n)
    Space Complexity: O(n)
    """
    num_map = {}  # {value: index}
    
    for i, num in enumerate(nums):
        complement = target - num
        
        if complement in num_map:
            return [num_map[complement], i]
        
        num_map[num] = i
    
    return []  # Should never reach here per problem constraints

# Test cases
print(twoSum([2,7,11,15], 9))  # [0, 1]
print(twoSum([3,2,4], 6))      # [1, 2]
print(twoSum([3,3], 6))        # [0, 1]
```

### Java Solution
```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> numMap = new HashMap<>();
        
        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            
            if (numMap.containsKey(complement)) {
                return new int[] {numMap.get(complement), i};
            }
            
            numMap.put(nums[i], i);
        }
        
        return new int[] {}; // Should never reach here
    }
}
```

### JavaScript Solution
```javascript
function twoSum(nums, target) {
    const numMap = new Map();
    
    for (let i = 0; i < nums.length; i++) {
        const complement = target - nums[i];
        
        if (numMap.has(complement)) {
            return [numMap.get(complement), i];
        }
        
        numMap.set(nums[i], i);
    }
    
    return [];
}

// Test cases
console.log(twoSum([2,7,11,15], 9)); // [0, 1]
console.log(twoSum([3,2,4], 6));     // [1, 2]
console.log(twoSum([3,3], 6));       // [0, 1]
```

## Complexity Analysis

| Approach | Time Complexity | Space Complexity |
|----------|----------------|------------------|
| Brute Force | O(n²) | O(1) |
| Hash Map | O(n) | O(n) |

**Why Hash Map is better:**
- For n=10,000 elements:
  - Brute Force: ~50 million operations
  - Hash Map: ~10,000 operations (5000x faster!)

## Common Mistakes

❌ **Mistake 1:** Using the same element twice
```python
# WRONG - checks if complement equals current element
if complement == num:
    return [i, i]
```

✅ **Fix:** Store elements BEFORE checking, or check map first then add

❌ **Mistake 2:** Returning values instead of indices
```python
# WRONG
return [complement, num]
```

✅ **Fix:** Return indices as required

❌ **Mistake 3:** Not handling the order correctly
```python
# WRONG - returns [current, previous] instead of [previous, current]
return [i, num_map[complement]]
```

✅ **Fix:** Return [num_map[complement], i]

## Interview Tips

💡 **What interviewers look for:**
1. Can you recognize the hash map pattern?
2. Do you optimize from brute force?
3. Can you explain the trade-offs?

💡 **Follow-up questions:**
- "What if the array is sorted?" → Use two pointers
- "What if there are multiple solutions?" → Return all pairs
- "What if we need to find 3 numbers?" → Extend to 3Sum

💡 **Key phrases to say:**
- "I'll use a hash map to store complements for O(1) lookup"
- "This reduces time complexity from O(n²) to O(n)"
- "Space-time tradeoff: using O(n) extra space for faster lookup"

## Reflection Questions

1. Why can't we sort the array first? (Answer: We need original indices)
2. What if there are duplicate numbers? (Answer: Hash map stores latest index)
3. How would you modify this for "find all pairs"? (Answer: Store list of indices)
