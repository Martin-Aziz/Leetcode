## 🧩 Problem Statement

Given an integer array `nums`, find the contiguous subarray (containing at least one number) which has the largest sum and return **its sum**.

A **subarray** is a contiguous part of an array.

### 📝 Examples

**Example 1:**
```python
Input: nums = [-2,1,-3,4,-1,2,1,-5,4]
Output: 6
Explanation: The subarray [4,-1,2,1] has the largest sum = 6.
```

**Example 2:**
```python
Input: nums = [1]
Output: 1
```

**Example 3:**
```python
Input: nums = [5,4,-1,7,8]
Output: 23
Explanation: The entire array has the largest sum = 23.
```

**Example 4:**
```python
Input: nums = [-1]
Output: -1
```

### 🔍 Input/Output Types
- **Input:** 
  - `nums`: List of integers (`List[int]`) - can contain negative numbers
- **Output:** Integer representing maximum subarray sum (`int`)

## 🧠 Understanding the Problem

**What is this problem really asking?**

You need to find the **maximum sum** possible from any contiguous portion of the array. You must pick at least one element (can't choose an empty subarray).

**Key Points:**
- ✅ Subarray must be **contiguous** (no skipping elements)
- ✅ Must include **at least one element**
- ✅ Array can contain **negative numbers**
- ✅ All negative numbers? Return the least negative (largest single element)
- ⚠️ Don't need to return the actual subarray, just its sum

**Edge Cases:**
- Single element array
- All negative numbers
- All positive numbers
- Mix of positive and negative
- Array with zeros

---

## 🧭 Recognizing the Pattern(s)

### 🎯 Primary Pattern: **Kadane's Algorithm (Dynamic Programming)**

**Analogy:** Imagine you're hiking and tracking your elevation gain. At each step, you ask: "Should I continue my current hike, or start fresh from here?" If your current hike has gone negative (you've lost more elevation than gained), it's better to start a new hike from the current position!

**Why This Pattern?**
- We need to make a decision at each position: **extend** the existing subarray or **start new**
- This is optimal substructure - the best solution depends on previous best solutions
- Kadane's algorithm solves this in O(n) time with O(1) space

**Alternative Patterns:**
- **Divide and Conquer** - Split array, solve recursively (O(n log n))
- **Brute Force** - Check all subarrays (O(n²) or O(n³))

## 🪜 High-Level Plan

### Strategy: Kadane's Algorithm

1. **Initialize two variables:**
   - `current_sum` = first element (best sum ending at current position)
   - `max_sum` = first element (global maximum found so far)

2. **Iterate through array starting from index 1:**
   - For each number, decide: **Start new** or **extend current**?
   - `current_sum = max(num, current_sum + num)`
     - If `current_sum + num < num`, start fresh from `num`
     - Otherwise, extend the existing subarray
   
3. **Update global maximum:**
   - `max_sum = max(max_sum, current_sum)`

4. **Return `max_sum`**

### 📋 Pseudocode

```python
# Step 1: Initialize
current_sum = nums[0]
max_sum = nums[0]

# Step 2: Iterate through rest of array
for i from 1 to len(nums)-1:
    # Decision: start new or extend?
    current_sum = max(nums[i], current_sum + nums[i])
    
    # Update global maximum
    max_sum = max(max_sum, current_sum)

# Step 3: Return result
return max_sum
```

## 🧑‍💻 Code Solution (Python)

### ✨ Optimal Solution: Kadane's Algorithm

```python
# Time Complexity: O(n) - Single pass through array
# Space Complexity: O(1) - Only two variables

def maxSubArray(nums):
    """
    Find maximum sum of contiguous subarray using Kadane's Algorithm.
    
    Args:
        nums: List of integers
    
    Returns:
        Maximum sum of any contiguous subarray
    """
    if not nums:
        return 0  # or raise exception based on requirements
    
    # Initialize with first element
    current_sum = nums[0]  # Best sum ending at current position
    max_sum = nums[0]      # Global maximum found so far
    
    # Iterate through rest of array
    for num in nums[1:]:
        # Key decision: extend existing subarray or start new?
        # If current_sum + num < num, it's better to start fresh
        current_sum = max(num, current_sum + num)
        
        # Update global maximum if we found a better sum
        max_sum = max(max_sum, current_sum)
    
    return max_sum


# ✅ Example Tests
print(maxSubArray([-2,1,-3,4,-1,2,1,-5,4]))  # Output: 6
print(maxSubArray([1]))                       # Output: 1
print(maxSubArray([5,4,-1,7,8]))             # Output: 23
print(maxSubArray([-1]))                      # Output: -1
print(maxSubArray([-2,-1]))                   # Output: -1
print(maxSubArray([-1,-2,-3]))               # Output: -1
```

### 🔄 Alternative Solution: Track Subarray Indices

```python
# Time Complexity: O(n)
# Space Complexity: O(1)
# Bonus: Also returns the actual subarray!

def maxSubArrayWithIndices(nums):
    """
    Returns both the maximum sum and the subarray indices.
    """
    if not nums:
        return 0, []
    
    current_sum = max_sum = nums[0]
    max_start = max_end = 0
    current_start = 0
    
    for i in range(1, len(nums)):
        # Decide whether to start new or extend
        if nums[i] > current_sum + nums[i]:
            current_sum = nums[i]
            current_start = i  # Start new subarray
        else:
            current_sum += nums[i]
        
        # Update global maximum
        if current_sum > max_sum:
            max_sum = current_sum
            max_start = current_start
            max_end = i
    
    return max_sum, nums[max_start:max_end + 1]


# ✅ Example Tests
result, subarray = maxSubArrayWithIndices([-2,1,-3,4,-1,2,1,-5,4])
print(f"Sum: {result}, Subarray: {subarray}")  
# Output: Sum: 6, Subarray: [4, -1, 2, 1]
```

## 🧩 Step-by-Step Explanation

Let's trace through **Example 1:** `nums = [-2,1,-3,4,-1,2,1,-5,4]`

### Initialization
```python
current_sum = -2
max_sum = -2
```

### Iteration 1: num = 1
```python
current_sum = max(1, -2 + 1) = max(1, -1) = 1
max_sum = max(-2, 1) = 1
# Decision: Start new subarray at index 1
```

### Iteration 2: num = -3
```python
current_sum = max(-3, 1 + (-3)) = max(-3, -2) = -2
max_sum = max(1, -2) = 1
# Decision: Extend current subarray (but it goes negative)
```

### Iteration 3: num = 4
```python
current_sum = max(4, -2 + 4) = max(4, 2) = 4
max_sum = max(1, 4) = 4
# Decision: Start new subarray at index 3 (value 4)
```

### Iteration 4: num = -1
```python
current_sum = max(-1, 4 + (-1)) = max(-1, 3) = 3
max_sum = max(4, 3) = 4
# Decision: Extend (still positive, keep going)
```

### Iteration 5: num = 2
```python
current_sum = max(2, 3 + 2) = max(2, 5) = 5
max_sum = max(4, 5) = 5
# Decision: Extend (getting better!)
```

### Iteration 6: num = 1
```python
current_sum = max(1, 5 + 1) = max(1, 6) = 6
max_sum = max(5, 6) = 6
# Decision: Extend (new maximum found!)
```

### Iteration 7: num = -5
```python
current_sum = max(-5, 6 + (-5)) = max(-5, 1) = 1
max_sum = max(6, 1) = 6
# Decision: Extend (but sum decreases)
```

### Iteration 8: num = 4
```python
current_sum = max(4, 1 + 4) = max(4, 5) = 5
max_sum = max(6, 5) = 6
# Decision: Extend
```

**Final Result:** `max_sum = 6` ✅

## ⏱️ Complexity Analysis

### Time Complexity: **O(n)**
- Single pass through the array
- Each iteration does constant work (comparisons and additions)
- Total: **O(n)** where n is array length

### Space Complexity: **O(1)**
- Only using two variables regardless of input size
- No extra data structures needed
- **O(1)** constant space

### 📊 Comparison of Approaches

| Approach | Time | Space | Difficulty | Notes |
|----------|------|-------|------------|-------|
| **Kadane's** | O(n) | O(1) | Easy | ✅ Optimal |
| **DP Array** | O(n) | O(n) | Easy | Uses extra space |
| **Divide & Conquer** | O(n log n) | O(log n) | Hard | Overkill for this |
| **Brute Force** | O(n²) | O(1) | Easy | Too slow for large inputs |

<summary><b>Question 1:</b> Why do we use `max(num, current_sum + num)` instead of just adding?</summary>

**Answer:** If `current_sum` is negative, adding it to `num` would make the sum smaller than just starting fresh with `num`. We want to maximize, so we choose the better option.

</details>

**Answer:** The algorithm still works! It will return the least negative number (the maximum single element), which is correct since we must pick at least one element.

</details>
